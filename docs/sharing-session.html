caddie01
The hook

Claude Code is great — until you've collected 70 skills and every project sees all of them.

The why02
The problem

One global pile. Or manual copies. Both lose.

  • Skill noiseEvery project sees every skill — Claude picks the wrong tool for the job.
  • Scattered reposSkills live across many git repos. Manual clone, manual copy, drift.
  • No per-project configModel, permissions, CLAUDE.md — all global, all the time.
  • Can't share a setup"Works on my machine" — but for AI tooling.
  • Sync is copy-pasteA skill updates? Re-clone, re-copy, hope nothing drifted.
  • Symlinks die in DockerYou can't ship the same skills to Lambda or CI.
The why03
The wish

I want cd into a project to give Claude exactly the right toolkit.

Like a golf caddie handing you the right club — without you asking.

The why04
The what

Meet caddie.

caddie scans many skill repos, indexes them under one namespace, and activates a curated subset per project — as symlinks.

Same laptop. Same Claude. Different toolkit per directory.

The what05
Four concepts

Repos, index, environments, bindings.

01

Skill repos

Git repos registered in sources.yaml. Auto-cloned, auto-pulled.

02

The index

One namespaced view of every skill. prefix:name, e.g. superpowers:brainstorming.

03

Environments

YAML profiles with glob patterns: superpowers:*, gws:gmail-*.

04

Bindings

Drop a .caddie.yaml in a project. caddie activate wires up the rest.

The what06
Architecture at a glance

Scan → Index → Activate.

The what07
The activation pipeline

$ caddie activate

  1. 1

    Read .caddie.yaml

    Project tells caddie which environment to load.

  2. 2

    Pull every registered repo

    Auto-throttled — at most once per hour.

  3. 3

    Rebuild the index

    Symlinks under ~/.config/caddie/skills/, namespaced.

  4. 4

    Resolve patterns

    superpowers:* → 22 skills, gws:gmail-* → 3 skills...

  5. 5

    Wire up project symlinks

    .claude/skills ready. Launch Claude.

The what09
Bonus

Symlinks die in Docker. Export resurrects them.

caddie export resolves every symlink and copies real SKILL.md files — to a folder or straight to S3.

→ Docker · Lambda · ECS · CI/CD

# local dir
caddie export backend-api \
  --to ./dist/skills/

# straight to S3
caddie export backend-api \
  --to s3://my-bucket/skills/

Get started yourself

Three commands and a config file.

  1. Installbrew install go · clone caddie · ./scripts/build.sh · copy to /usr/local/bin/
  2. Initializecaddie init — backs up ~/.claude/skills/ and sets things up.
  3. Register a skill repocaddie repo add superpowers https://github.com/Portauw/superpowers.git
  4. Create an environmentcaddie create my-project (interactive)
  5. Bind & activateDrop environment: my-project in .caddie.yaml · run caddie activate
